# Architecture (Pass 1, as built)

This file is the source of truth for how the code is put together. Read it before a re-pass. The
design brief is `PASS1_SPEC.md` and the canon is `WORLD_BIBLE.md`. The AI and the comms engine have
their own files (`AI_SYSTEMS.md` and `COMMS_GRAMMAR.md`).

## The one rule

**There is one simulation, and every seat reads it through its own perception.** The Human POV, the
AI POV and the headless batch runs all build the same `Session` from the same scenario. Only
*who drives which seat* differs between them. No agent ever reads ground truth. That covers our AI,
the simulated pilot, enemy AIs and enemy pilots. Ground truth reaches only the referee code (the
objectives, the claims resolver and the debrief), and that code never feeds anything back into an
agent.

```
scenario (seeded) ──► Session ──► World (entities, fixed DT = 1/30 s, systems at their own Hz)
                         │
     per crewed ship:    ├── SensorSuite (physical sensors → RAW frames + measurements)
                         ├── ShipMind    (tracker → classifier → assessment)        ┐ seat 'ai'
                         ├── ShipAgent   (utility reasoners → exterior commands)    ┘
                         └── PilotAgent / SimplePilot (physiology, DDM, motor)      ─ seat 'pilot'
     player ship:        ├── crewChannel (AI ↔ pilot intents)  ──► CommsEngine (Layer 2 words)
                         ├── ClaimsRegistry + resolver (referee)
                         └── ObjectiveEvaluator (referee)
```

## Layout

| path | what |
|---|---|
| `js/core` | seeded RNG with named streams, Float64 vector/quaternion math, the event log (single source of truth for "what happened") |
| `js/data` | hull and kit specs (`hulls.js`), names, `cockpit_layout.json` (generated by `tools/gen_cockpit_layout.mjs`, consumed by Blender **and** the runtime), `hull_layout.json` (exported from the as-built assets) |
| `js/sim` | orbital mechanics, ship systems (power, thermal, life support, propulsion, interior state), sensors, tracker and classifier, weapons, damage, scenario generator, objectives, `Session` |
| `js/ai` | the utility reasoner, ship mind and agent, planner, fire control, the pilot (agent, compliance DDM, motor), trust, claims, personality sampling |
| `js/comms` | intents, grammar, formatters, styles, lexicons, `CommsEngine`, player intents for both POVs |
| `js/roster` | the Roster stub (Person, AIEntity, ShipRecord, Relationship, HistoryLog), the after-action write-back, the War State Ledger |
| `js/render` | three.js only: renderer (far and near passes), sky, world view, cockpit, pilot rig, feeds, screens, effects, asset library |
| `js/app` | `Game` (one encounter), `HumanControl` (pilot seat), `AIView` (AI seat composite) |
| `js/ui` | menu and briefing, HUD (subtitles, chat, pause), debrief, debug panel |
| `js/voice`, `js/audio` | speechSynthesis with karaoke; procedural cabin audio |
| `blender/` | headless bpy 5.2.3 asset pipeline (see `blender/README.md` and `ASSETS.md`) |
| `tools/` | build (single file), dev server, batch runner, smoke test, cockpit layout generator, asset viewer |

`js/sim`, `js/ai`, `js/comms` and `js/roster` contain no DOM code and no three.js. They run under
Node for the tests and the batch runs.

## Build

- `three@0.186.1` and `esbuild@0.28.2` are pinned exactly and vendored from npm, so the game makes
  no network calls at runtime.
- `tools/build.mjs` bundles `js/main.js` into an IIFE and embeds every GLB and texture through the
  `virtual:assets` binary loader. It inlines the result into `index.html` (about 34 MB), which works
  from `file://` when you double-click it.
- `dev.html` plus `tools/serve.mjs` serve the same bundle and rebuild it on reload.

## Simulation

- **Frame and integration.** Everything is in a Moon-centred inertial frame in doubles. Gravity is
  two-body plus J2, plus Earth and Sun third-body terms, integrated with RK4.
  `World.addSystem(name, hz, fn, phase)` schedules subsystems at their own rates. Sensors run every
  step, minds at 2 Hz, agents at 1 Hz, PD at 4 Hz, crews at 2 Hz and objectives at 1 Hz.
- **Light lag.** Every entity keeps a history ring buffer. An observation samples the emitter's
  *retarded* state, and radar wavefronts expand at c until each RWR hears them.
- **Doctrine.** `Ship.exteriorCommand(actor, …)` accepts only the `ai` seat, and
  `InteriorState.actuate(actor, …)` accepts only the `pilot` seat. Anything else throws
  `DoctrineViolation`. Physics can still move interior state, as when a breaker trips.
- **Determinism.** Seeded RNG streams are named by role (`mind-<key>`, `sensors-<key>`, …), and the
  id sequences reset per session. The same seed replays the same world, which
  `test/determinism.test.js` checks. Player inputs, the player's motor system and the AI-POV
  reflexes then make each run diverge.

## Rendering

- **Two passes.** The far scene (Moon, Earth, Sun, stars and far glints) uses km-scale clipping.
  The depth buffer is then cleared and the near scene (ships, effects, cockpit) draws with cm-scale
  clipping. A floating origin at the player ship keeps GPU floats small.
- **Lighting.** The only key light is the Sun, which casts shadows. The other lights are physical
  fills: lunar albedo bounce, earthshine, the instrument lamps (physically scaled, red at night)
  and an interior bounce light. The bounce is scaled by a ray probe that tests whether sunlight
  actually enters the cabin.
- **Exposure.** Eye adaptation sets exposure for the whole frame. The NIR illuminators for the
  cabin cameras switch on only while those feeds render.
- **Assets.** Assets carry a COLOR_0 mask (R = AO, G = edge wear, B = cavity). An `onBeforeCompile`
  hook turns it into chipped paint and grime, with triplanar detail maps.
- **Cockpit controls.** Every control animates generically from glTF extras
  (`anim/axis/values/states`). The same state moves the switch whether the player, the simulated
  pilot or physics changed it.
- **Screens.** A canvas is composited over an optional render-target feed by a shader. Brightness
  and flicker follow the real bus voltage. RAW layers are green and white, and the AI layer is
  amber; the two never mix unless the pilot flips the overlay switch.
- **Feeds.** `FeedManager` renders watched feeds round-robin under a per-frame budget. These are
  the optical sensor and telescope (looking where the real sensor points, with its real FOV), the
  exterior hull cameras and the cabin cameras.

## Seats

- **Human POV (`HumanControl`).**
  - Seated mouse look from the design eye point, with head-spring sway and lean.
  - Clicking a control queues a reach in the pilot's `MotorSystem`: Fitts' law timing, g-load,
    tremor, and slips onto the neighbouring switch. The IK arm then animates it.
  - CONFIRM and DENY resolve the AI's most urgent pending request.
  - The bezel softkeys page the MFDs.
  - Right-clicking a raw page runs **Check this**, a track-before-detect integration at that
    point, which can confirm or reject a contact.
- **AI POV (`AIView`).**
  - The player's agent has `enabled = false`. The player picks exterior actions from the planner
    (`generateCandidates`), fire options (`ShipAgent.fireOptions`), sensors, radiators and the
    relay.
  - Gated actions become requests on the pilot's board. The pilot then deliberates through the
    same DDM.
  - The AI's low-level reflexes (point defence, sensor scheduling, radiators) can stay on
    automatic.
  - Speech is player-only: the comms engine drops autonomous AI lines in this mode.

## Testing

| command | what it checks |
|---|---|
| `npm test` | physics conservation, Tsiolkovsky, light lag, tracker consistency (NEES), radar range collapse, classifier calibration, weapons, grammar coverage and variety (both lexicons), determinism |
| `node tools/sim_batch.mjs --variant all --n 20` | AI-vs-AI outcome distributions per variant (the outcomes must vary) |
| `npm run smoke` | the built file under `file://`, all six mode × variant combinations, with fast-forward, debrief and screenshots |
